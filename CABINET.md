# Кабінет курсу — налаштування

## 1. Supabase

1. Створити проєкт на [supabase.com](https://supabase.com).
2. SQL Editor → виконати по черзі:
   - `supabase/migrations/0001_init.sql` (таблиці, RLS, тригери)
   - `supabase/migrations/0002_seed.sql` (6 модулів, 24 уроки)
3. Authentication → Providers → **Email**: увімкнути,
   вимкнути «Confirm email» не треба — вхід іде через magic link.
4. Authentication → URL Configuration → Redirect URLs додати:
   - `http://localhost:3000/auth/callback`
   - `https://ТВІЙ-ДОМЕН/auth/callback`
5. Project Settings → API — скопіювати `URL`, `anon key`, `service_role key`.

## 2. monobank

1. [web.monobank.ua](https://web.monobank.ua) → Розробникам → отримати `X-Token`
   для еквайрингу.
2. Вебхук налаштовувати не треба — URL передається при створенні рахунку.
3. **Вебхук працює лише на публічному домені.** Локально — через
   `ngrok http 3000` і `NEXT_PUBLIC_SITE_URL=https://xxx.ngrok.io`.

## 3. Пошта (SMTP)

Вбудований поштовик Supabase дозволяє лише **2–3 листи на годину** — цього
вистачає для тестів, але не для продажів: якщо курс купить кілька людей
поспіль, більшість не отримає доступу.

Тому перед запуском треба підключити власний SMTP. Resend — безкоштовно
3 000 листів/міс (100/день), цього з головою.

1. Зареєструватись на [resend.com](https://resend.com).
2. **API Keys** → Create API Key → скопіювати (показується один раз).
3. Supabase → **Authentication → Emails** (розділ NOTIFICATIONS
   у лівому меню) → вкладка **SMTP**:

   > У старіших версіях панелі це було в Project Settings → Authentication
   > → SMTP Settings. Якщо не знаходиш — шукай розділ «Emails».

   - Enable Custom SMTP: **увімкнути**
   - Host: `smtp.resend.com`
   - Port: `465`
   - Username: `resend`
   - Password: *(API key з кроку 2)*
   - Sender email: `onboarding@resend.dev` — щоб стартувати без домену.

     > ⚠️ Це поле треба **справді заповнити**. Сірий `noreply@yourdomain.com`
     > у полі — це плейсхолдер, а не значення. Якщо його не замінити,
     > Resend відхиляє всі листи з помилкою `550 domain is not verified`,
     > а Supabase у відповідь віддає 500 «Error sending confirmation email».

     Коли підтвердиш свій домен у Resend (Domains → Add Domain, додати
     DNS-записи) — замінити на `noreply@твій-домен`.
   - Sender name: `Kotova Taping Academy`
4. Зберегти. Ліміт листів зникне.

Шаблон листа англійською за замовчуванням — змінюється в
**Authentication → Email Templates → Magic Link**.

## 4. Змінні оточення

Скопіювати `.env.example` → `.env.local` і заповнити.
На Vercel ті самі змінні додати в Project Settings → Environment Variables.

## 5. Відео

Уроки створюються сідом без відео — сторінка показує заглушку
«Відео ще завантажується».

### Підключити цілий плейлист

Українська версія курсу лежить на YouTube окремим плейлистом,
доступним за посиланням. Щоб прив'язати його до уроків:

```bash
# 1. Спочатку подивитись, що з чим зіставиться (нічого не пише в базу):
node scripts/link-videos.mjs "https://www.youtube.com/playlist?list=..."

# 2. Якщо все навпроти правильних уроків — записати:
node scripts/link-videos.mjs "https://www.youtube.com/playlist?list=..." --apply
```

Відео зіставляються з уроками **по порядку**: перше відео плейлиста —
перший урок модуля 01 і далі. Тому порядок у плейлисті має збігатися
з порядком уроків у курсі. Скрипт показує назву відео поруч із назвою
уроку — перед `--apply` варто пробігтись очима.

### Підключити один урок

```sql
update public.lessons set video_id = 'ВАШ_ID'
where slug = 'module-01-l1';
```

### Про захист відео

Плейлист «за посиланням» захищений лише незнанням адреси: ID видно
в DOM плеєра, його можна переслати будь-кому. Для курсу за $499
це реальний ризик.

Провайдер винесено в поле `lessons.video_provider` і окремий `case`
у `VideoPlayer` — перехід на Bunny Stream (підписані URL, ~$5–10/міс)
зачепить лише ці два місця.

### Англійська версія

Відкладена: запускаємось українською. Коли англійські відео будуть
на YouTube, найпростіший шлях — додати поле `video_id_en` і перемикач
у плеєрі (уроки та схема інших змін не потребують).

## 5.5. Вхід без пошти (поки немає домену)

Resend не верифікує `*.vercel.app`, тому magic link доходить **лише
на пошту власника акаунта Resend**. Поки домену немає, пошта не може
бути основним каналом — інакше покупець платить і лишається без доступу.

Тому входів три, і жоден із них не залежить від листа:

### 1. Одразу після оплати (основний)

monobank повертає на `/thanks?ref=<reference>`. Сторінка стукає в
`/api/claim`, той **питає статус рахунку в monobank напряму** і, якщо
оплачено, ставить куки сесії. Людина в кабінеті тим самим кліком.

Довіряти самому поверненню не можна — `redirectUrl` лишається в історії
браузера. Тому:
- статус беремо з monobank, а не з параметрів URL;
- сума звіряється з `orders.amount`;
- посилання одноразове (`orders.auto_login_used_at`).

### 2. Код доступу (інший пристрій)

Після оплати показується 6-значний код і лежить в `orders.access_code`.
На `/login` — пошта + код → сесія. Працює скільки завгодно разів.

Захист від перебору: `orders.code_attempts`, 8 спроб, далі 429.
Відповідь на «немає рахунку» і «невірний код» однакова, щоб не можна
було перебором дізнатись, хто купив курс.

Подивитись код клієнта:
```sql
select email, access_code, code_attempts
from public.orders where email = 'student@example.com';
```

### 3. Telegram-бот (запасний канал)

`/start` → бот просить номер кнопкою `request_contact` → знаходить
оплату за номером → присилає кнопку входу. Номер від Telegram
**верифікований**, тому SMS і Twilio не потрібні.

З `/thanks` є кнопка «зберегти доступ у Telegram» — вона веде
на `t.me/бот?start=<token>`, і бот одразу знає, кому відкривати.

Посилання входу (`/tg/<token>`) одноразове і живе 15 хвилин.

**Тому телефон при оформленні обовʼязковий** — без нього цей шлях
не працює.

### Налаштування бота

1. [@BotFather](https://t.me/BotFather) → `/newbot` → отримати токен.
2. У `.env.local`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC...
   NEXT_PUBLIC_TELEGRAM_BOT=kotova_taping_bot   # без @
   TELEGRAM_WEBHOOK_SECRET=довгий-випадковий-рядок
   ```
3. Зареєструвати вебхук (потрібен https — тобто Vercel або ngrok):
   ```bash
   node scripts/setup-telegram.mjs --set
   node scripts/setup-telegram.mjs          # перевірити стан
   ```

Telegram не підписує запити, тому секрет у `TELEGRAM_WEBHOOK_SECRET`
обовʼязковий — інакше вебхук приймає будь-що від будь-кого.

### Чи треба буде переробляти, коли зʼявиться домен

Ні. Magic link уже лежить другою вкладкою на `/login` і почне
працювати сам, щойно Resend верифікує домен. Код і Telegram
лишаються — вони зручніші за лист.

### Скільки живе сесія

Куки httpOnly + refresh token, які оновлює middleware на кожному
запиті. За замовчуванням Supabase тримає сесію **30 днів** із
ковзним продовженням: хто заходить хоч раз на місяць — не вводить
нічого ніколи. Термін міняється в Supabase → Authentication →
Sessions.

## 6. Як це працює

```
Оплата:  Offer → BuyButton → /api/checkout → monobank invoice
                                     ↓
         сторінка оплати monobank → /api/mono/webhook (перевірка підпису)
                                     ↓
         grantAccess(): user + enrollments + код доступу
                                     ↓
         повернення на /thanks?ref=… → /api/claim (звірка з monobank)
                                     ↓
                        сесія в куках → кабінет відкрито

Вхід:    код доступу  → /api/code   → сесія
         Telegram     → /tg/<token> → сесія
         magic link   → /auth/callback → сесія   (коли буде домен)
```

### Як учень потрапляє в кабінет

Чотири незалежні шляхи — щоб людина не загубилась, якщо один не спрацює.
Детально — у розділі 5.5.

1. **Одразу після оплати** — сесія ставиться автоматично на `/thanks`.
2. **Код доступу** — показаний після оплати, вводиться на `/login`.
3. **Telegram** — бот знаходить оплату за номером телефону.
4. **Лист** — запрацює, коли зʼявиться домен для Resend.

Пароля немає ніде.

### Якщо вебхук не дійшов

`hasAccess()` у `src/lib/course.ts` підстраховує: якщо enrollment немає,
але на цю пошту є оплачений рахунок, він питає monobank напряму
(`invoice/status`) і відкриває доступ. Тому оплата не губиться навіть
без вебхука — доступ зʼявиться при першому вході.

Доступ перевіряється у двох місцях:
- **middleware** — редіректить неавторизованих з `/cabinet` на `/login`;
- **RLS у БД** — навіть із валідним токеном закриті уроки не віддаються.

## 7. Ціна і валюта

Ціна вказана в **доларах** (`offer.price` у `src/content.ts`), а monobank
виставляє рахунки лише в гривні. Курс тягнеться з API НБУ
(`src/lib/fx.ts`), кешується на 6 годин, при збої API є резервний курс.

Сума рахунку фіксується в `orders.amount` при створенні — і вебхук,
і звірка порівнюють саме з нею, тому коливання курсу нічого не ламають.
